## 一句话

让一家小店的收银机能独立跑在断网环境，让十家连锁店的总老板打开浏览器就能看到所有门店实时经营数据。

---

## 解决什么问题

### 1. 传统收银设备依赖云端，一断网就瘫痪
柒号从内核层就是**离线优先**的核心设计：订单创建、支付、会员扣款、库存扣减全部走本地 SQLite + WAL 模式，公网断了收银照跑、小票照打、会员照刷。

### 2. 连锁门店数据散乱，老板要看数得挨家问
柒号 POS 端每日签名打包经营数据，通过 HTTPS push 到云端聚合服务。总部看板无需逐台 POS 拉数据，连锁母店 License 登录即可看到所有子店的实时排名、趋势与占比。

### 3. 小店买不起动辄上万的连锁 SaaS
柒号定价清晰：单店版 ¥399/年、5 店旗舰 ¥1,599/年、不限门店 ¥3,999/年。License 激活即用，无需部署昂贵服务器，小本生意也负担得起。

### 4. 硬件整合难，各家厂商驱动不统一
柒号内置扫码枪、小票打印机、电子秤、客显收款码屏四类常见外设的驱动框架，旁路插件式接入，未接入时收银主流程不受影响。

## 创新点

### 🪪 License 激活码 = 身份 + 授权 + 店名
License 不仅是功能开关，还是门店的数字身份证：

- **激活码绑定店名**：POS 端显示在屏幕右上角和小票票头，商家**无法在本地修改**，杜绝"招牌与执照不一致"的合规风险。
- **激活码区分单店/连锁**：`single` / `chain_parent` / `chain_node` 三种类型，决定系统开放哪些能力（看板视图数、跨店汇总、实时 WebSocket 推送）。
- **硬件指纹绑定**：一机一 License，防止商家买了 1 店 License 装 10 台机器。

### 🔒 从源头防数据丢失与篡改

| 风险 | 柒号做法 |
|------|---------|
| Token 撤销列表重启清零 | Token `jti` 持久化到 SQLite，重启保留 |
| 退款并发重入 | CAS 状态机 (`paid → refunding → refunded`) 原子化 |
| 店名本地任意改 | License payload 锁定，UI 灰态禁编辑 |
| 云端数据伪造 | POS 端 RSA-SHA256 签名，云端验签入库 |
| SQL LIKE 注入 | 统一转义函数 (`%_\`) 防通配符 |

### 🎛️ 旁路 Agent 层：AI 能力不打扰主流程
柒号把商品推荐、异常检测、库存预警设计成**旁路 Agent**，旁路挂接事件总线，主收银路径永远不阻塞——哪怕 Agent 因模型超时故障，收银台仍然秒级响应。

### 📊 数据可视化内嵌，无需第三方
本地 POS 即可打开 7 视图数据看板（概览 / 趋势 / 品类 / 时段 / 会员 / 收银员 / 连锁对比）， Chart.js 纯前端渲染，不依赖任何外部 BI 工具。

## 架构简介

### 整体分层 (DDD 领域驱动)

```
┌─────────────────────────────────────────┐
│  前端 SPA (零依赖原生 HTML/JS/CSS)       │
├─────────────────────────────────────────┤
│  API 层  (FastAPI + Pydantic v2)        │
├─────────────────────────────────────────┤
│  应用层  (用例编排 Service)             │
├─────────────────────────────────────────┤
│  领域层  (Order/Product/Member 聚合)    │
├─────────────────────────────────────────┤
│  基础设施  (SQLite WAL / 硬件驱动 / 同步) │
└─────────────────────────────────────────┘
```

- **Domain** 层定义 `Order`、`Product`、`Member` 等聚合根与值对象，不依赖任何框架。
- **Application** 层编排 `CheckoutService`、`MemberService`、`ProductService` 等用例。
- **API** 层仅做 HTTP 入参校验与响应序列化，薄适配。
- **Infra** 层封装 SQLite 访问、硬件驱动、云同步队列，可替换。

前端样式采用 `tokens-merged.css` 统一设计令牌系统，合并了色彩（中性/语义/行业/订单状态）、8pt 网格间距、四级圆角与阴影、玻璃拟态、动效曲线等令牌，通过 `:root` 变量层零依赖实现主题切换（含暗色）。

### 云端聚合 (独立进程)

POS 与云端**物理解耦**：

- 收银端 (`cashier serve`, 端口 8000): 单机收银台。
- 云端 (`python -m cloud.main`, 端口 9000): 聚合跨店日结数据。

POS 每日 23:55 自动把 RSA 签名的日结摘要 push 到云端。云端只做只读聚合与展示，不持有业务主数据，安全边界清晰。

### 实时推送 (WebSocket 双向)

POS push 触发时，云端 `ConnectionManager` 向该母店所有连接的 Dashboard 广播 `digest.new` 事件，看板即时刷出"XX店新数据入库"提示并重新拉取。

## 快速上手

```bash
# 克隆 → 安装 → 初始化 → 启动
git clone https://github.com/54ziqi/cashier-system.git
cd cashier-system
pip install -e .
cashier init
cashier license --trial 30
cashier serve --profile lite
# 浏览器打开 http://127.0.0.1:8000
```

- 首次登录账号密码见 `~/.cashier/data/initial-password.txt`，登录成功后**该文件自动删除**。
- 商家后台: `http://127.0.0.1:8000/dashboard`
- Swagger API 文档: `http://127.0.0.1:8000/docs`

启动云端聚合服务：

```bash
python -m cloud.main --port 9000
# 浏览器打开 http://9000 输入 License Key 登录
```

运行测试：

```bash
pytest -q
# 全量业务 + 看板 + 云端 + 推送 全绿
```

## 技术选型

| 层 | 选型 |
|----|------|
| 语言 | Python 3.10+ |
| Web 框架 | FastAPI + Uvicorn |
| 持久化 | SQLAlchemy 2 + SQLite (WAL) |
| 鉴权 | bcrypt + HMAC Session Token + DB 持久化撤销表 |
| 许可证 | RSA-PSS 签名 + AES-GCM 硬件指纹绑定 |
| 前端 | 原生 HTML5 / CSS / Chart.js（零构建步骤） |
| 硬件 | pyserial / python-escpos / qrcode（可选） |
| 推送签名 | RSA-SHA256 + HTTPS |
| 实时 | WebSocket 双向 (云端聚合) |
